## Summary

Fixed CI failure in PR #3 (feat/real-fault-viewer). Viewer tests depended on gitignored data artifacts (synthetic.zarr, fault_prob.zarr, fault-stick .dat files) absent in CI runner → 11 failed + 7 errors.

## Root Cause

Three test classes in `src/tests/test_viewer/test_viewer.py` relied on:
- `data/volve/staged/synthetic.zarr` (FileNotFoundError in CI)
- `data/volve/staged/fault_prob.zarr` (reader returned None, assertion failed)
- `data/volve/interpretations/fault_sticks/*.dat` (absent, "No .dat files found")

Additionally, one guard was inverted: test would pass when files were missing and fail when present.

## Fix Applied (Commit dab69c8)

### Tier 1 — Critical regression guard: synthesize fixture

Refactored `TestFaultStickCoordinateMapping` (highest-value test, guards z-as-sample-index coordinate bug) to use `tmp_path_factory` fixture writing minimal synthetic `.dat` files (3 rows each) covering full pinned coordinate ranges (808–908 ms main fault, 1200–1228 ms antithetic). Regression math fully proven on synthetic data.

Result: 8 coordinate-mapping tests run in CI with zero data dependencies.

### Tier 2 — Real-artifact readers: skip gracefully

Decorated `TestAmplitudeReader` and `TestFaultProbReader` with:

```python
@pytest.mark.skipif(
    not _ZARR_PATH.exists(),
    reason="data/volve/staged/X.zarr absent — run scripts/bake_demo_faults.py to generate",
)
```

- Self-documents exactly which artifact is missing and how to fix it
- Tests skip silently in CI, pass locally where data exists
- Fixes inverted-guard bug: assertions now accurate when files are confirmed present
